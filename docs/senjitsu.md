# 選日算出モジュール（ツキヨミ Threads投稿v2 用）

一粒万倍日・母倉日・天恩日・三隣亡・日の干支を**計算で**出す。年次JSONの手作業メンテは不要。

## 使い方

```python
import senjitsu as S, datetime
d = datetime.date(2026, 9, 6)

S.lucky_labels(d)   # ['一粒万倍日', '母倉日', '天恩日'] ← 文面生成はこれだけ見ればよい
S.describe(d)       # 干支・節月・各判定を含む dict
S.dump_range(a, b)  # 期間分のリスト
```

依存は `ephem` のみ（`pip install ephem`）。

## 規則の出典

- 一粒万倍日・三隣亡: 国立国会図書館「日本の暦」第三章
  https://www.ndl.go.jp/koyomi/chapter3/s6.html （節月×日の十二支、2通り併用）
- 天恩日: 「暦林問答集」の15干支（月に無関係・5日連続×3組）
  https://www.linderabell.com/entry/gedan/tenon
- 母倉日: 公開一覧から節月×十二支を逆算（矛盾ゼロで一意確定）

## 実装で踏んだ罠（2つとも実際にズレた）

1. **日の干支の基準日は実測すること。**
   「1984-02-02 = 甲子」は誤り。これを使うと全日程が2日ずれる。
   正しくは 2026-08-18 = 甲子（外部カレンダーで実測・寅の日/巳の日でも裏取り済み）。

2. **節月の境界は「節入りの瞬間」ではなく「節入り日の 0:00 JST」。**
   節が日中に入っても、その日は丸ごと新しい節月として扱うのが暦の慣習。
   瞬間で切ると節入り日が旧節月に落ち、一粒万倍日が年に数日ずれる。
   例: 2026年の白露は 9/7 23:41 JST だが、9/7 は終日「節月8」。

## 注意（文面生成側の責任）

- **日付や時刻を焼いた文面は当日限りで破棄すること。** 実行が失敗した枠を翌日に流用すると
  「9月6日は一粒万倍日」が嘘になる。
- 不成就日（凶日）は旧暦月基準のため未実装。吉日を打ち消す扱いをする場合は別途必要。

## 追加API（v1.1）

### `peak_window(date)` — 時間窓
その日の十二支と同じ時辰を返す。「その日の気が最も濃い時間」として暦の理屈が立つ。

```python
S.peak_window(datetime.date(2026,9,6))
# {'shi':'未','name':'未の刻','start':'13:00','end':'14:59','label':'13:00〜14:59'}
```

**参考投稿の「5:00〜8:59」は暦の裏付けがない任意の窓。** 毎回同じ時間を使い回すと、
同じ文面を撃っているのと同じに見える。時辰は日ごとに変わるのでその問題も出ない。

### `rarity.plan(date)` — T1を出すかの判断
吉日は年の49%あり、**最長9日連続する**。全部を等価に「特別な日」と言うと特別さが消える。

```python
import rarity
rarity.plan(datetime.date(2026,9,6))
# {'tier':3,'tier_name':'peak','freq_per_year':5,'use_T1':True, ...}
```

2026年実測の tier 分布:

| tier | 意味 | 日数 |
|---|---|---|
| 3 peak | 3種重なり（年5日だけ） | 5 |
| 2 strong | 2種重なり / 一粒万倍日単独 | 74 |
| 1 mild | 母倉日 or 天恩日の単独 | 101 |
| 0 skip | 選日なし | 185 |

**`use_T1` は tier>=2 の79日（年22%）だけ true。** 「ラベルがある日=180日でT1」にすると、
天恩日は5日連続で来るので「今日は天恩日です」を5日続けて出すことになる。

### 出現頻度（2026年実測・365日中）
天恩日91 / 母倉日72 / 一粒万倍日64。組み合わせ別は `rarity.FREQ_2026`。
3種重なりは **5/5・7/7・9/6・11/4・12/1 の年5日のみ**。
